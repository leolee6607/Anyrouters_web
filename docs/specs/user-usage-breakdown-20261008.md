# 用户消费构成统计

用户指出用量日志的“用户信息”弹窗只有累计消费，缺少模型与占比；要求正规、方便以后统计。沿用已上线月度消费的历史 quota 口径，扩展同一功能。

- 用量日志的用户信息弹窗提供“查看模型与渠道占比”，切换到同一用户的消费统计；用户列表月度消费入口继续可用。禁止旧账户请求晚返回显示到新账户。
- 报表支持月度账单、按模型、按渠道三种视图；后两种按所选年份合计或某个自然月统计。默认选择上一个完整自然月（当月核算上月，1 月默认上一年 12 月）；明确年份合计不是账号终身累计，当前月截至查询时间，固定北京时间。
- 模型名称取历史日志 model_name，不根据渠道当前模型猜测；空模型显示“未记录模型”，不丢弃退款或历史数据。相同模型跨渠道合并；渠道按 ID 汇总，已删除渠道仍保留编号。
- 扣费占比 = 此模型/渠道历史扣费 quota ÷ 所选周期全部历史扣费 quota。金额不重新计价、不重复应用折扣。退款、净消费和消费记录数另列；无扣费分母时占比为空/破折号，不能除零。占比保留两位，独立四舍五入合计可能有误差。
- 查询一次单用户/单年份的日志聚合，再输出月度与年度的模型/渠道分组。每个维度单独加总均等于周期总额，不能把模型和渠道交叉重复计费。
- 保留既有月度渠道 CSV；模型/渠道构成导出带视图、周期、用户、查询时间、扣费/退款/净额、占比基准、记录数；金额精确、不经过浮点重算、防 CSV 公式注入。
- 管理员鉴权与限流、15 秒超时、独立 LOG_DB、no-store 与关闭清理缓存沿用；不加表，不改余额，不影响现有扣费链。
- 验证跨模型/渠道/月份、退款大于扣费、仅退款、零扣费、用户隔离和月界；类型/lint/构建与真实管理页面、CSV 核对；GitHub/Notion 交接与可回退发布。
