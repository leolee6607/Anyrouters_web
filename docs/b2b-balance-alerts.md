# B2B 客户余额提醒

B 端分组卡片增加“用量提醒”。管理员选择组内客户后，可以填写剩余余额阈值（美元）、最多 10 个收件邮箱，分别执行测试发送和保存设置。新客户默认关闭，阈值预填 100 美元，可手动修改。测试不会保存设置、开启提醒或调整账户额度。

提醒按客户账户的可用余额监测，包含该账户所有 API Key 的使用，不按单个 Key 或分组总额计算。邮件包括客户编号、分组、余额、阈值、累计使用量和 B 端页面链接。累计使用量不是本月账单。邮件逐个收件人发送，不公开其他收件地址。

## 运行与状态

- master 节点每分钟检查一次，读取账户余额。额度低于阈值时发送一次；观察到余额恢复到阈值或以上后重新进入监测。
- 收件人分别记录 SMTP 已接受状态；部分失败时，5 分钟后只重试失败收件人。等待重试期间仍检查余额，恢复后取消本轮重试。
- 客户移出配置对应的分组、被删除或变为管理员时，暂停该提醒。重新配置新组需要显式保存。被停用客户暂不发送。
- 配置修订号阻止并行编辑覆盖；数据库租约协调副本，获取租约后重新读取投递状态，防止使用其他副本发送前的旧快照。
- SMTP 每次对话总超时 15 秒，要求 TLS；每封发送前续租。租约过期的旧任务不能开始发送。
- 测试发送使用现有管理员通知限流，最多 3 个并行 SMTP 连接。

常规重启和并发可去重；SMTP 接受与数据库落库不是同一个事务，进程恰好在二者之间退出时仍可能重复发送，不能宣称严格一次投递。SMTP 接受也不代表已进收件箱。分钟轮询可能错过两次检查之间的短暂充值恢复，极端用量增长也可能在下一次检查前耗尽余额。

## 接口与存储

以下接口都在现有 AdminAuth 下，普通客户不能读取、配置或测试：

- GET `/api/btob/balance-alerts?group=...`
- PUT `/api/btob/balance-alerts`
- POST `/api/btob/balance-alerts/test`

新增提醒状态表 `B2BBalanceAlert`（实际表名由 GORM 生成），客户 ID 为主键。正常和快速迁移路径均已登记；SQLite 测试通过，SQL 使用 GORM 以兼容 MySQL、PostgreSQL。生产发布已验证 MySQL 新表读取；PostgreSQL 未在真实实例执行迁移验证。

不修改钱包、Key 剩余额度、折扣、消费记录及客户原有个人通知设置，不自动续额或向聊天群发送消息。新增功能默认不产生任何邮件。

## 同批界面修复

- B 端页面取消固定内容高度限制，分组列表可以独立滚动，保持页头及外层页面位置。
- Key 列表显示“剩余”和“已使用”；编辑输入框明确设置剩余额度，历史使用量保留。原 `$10 / $17.23` 示例对应剩余 `$10`、已使用 `$7.23`，这次只更改说明和展示。

## 验证

- `go test ./common ./model ./service ./controller -count=1`
- `go test -race ./service ./controller ./common -run 'TestB2B|TestSendEmailWithTimeout' -count=1`（common 超时测试名称不同，已由上一项覆盖）
- `go build -o /tmp/anyrouters-b2b-alerts-check .`
- default 前端 typecheck、相关文件 ESLint / Prettier、default 与 classic 生产构建。
- Playwright 本地模拟接口：5 种视口滚动；桌面/手机自定义阈值、多邮箱、测试不保存不开启、保存回读、非法邮箱阻止；Key 剩余/已用显示及编辑文案。

本地邮件测试使用模拟发送器或本机超时接收端。发布时经用户授权，通过真实页面向单个指定收件邮箱发送了一封测试邮件，SMTP 已接受；没有保存配置或启用自动提醒。管理员仍需填写实际收件邮箱、确认收信后，再开启对应客户提醒。
