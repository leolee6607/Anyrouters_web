# usagetool 使用说明（站内日级导出 + 离线对账）

工具代码：`cmd/usagetool`（CLI 入口）+ `pkg/usagerecon`（实现与测试）。
只读、离线：export 只对 logs 表做 SELECT；reconcile 完全不连数据库。

## 构建

```bash
go build -o usagetool ./cmd/usagetool
```

## 1. 站内日级导出

```bash
./usagetool export \
  --db-type mysql \
  --dsn 'user:pass@tcp(host:3306)/newapi' \
  --from 2026-08-01 --to 2026-09-01 \
  --tz UTC \
  --channel-map channel_map.yaml \
  --out site_daily.csv
```

- `--db-type`：`sqlite` / `mysql` / `postgres`；`--dsn` 按对应驱动格式。
- `--from` 含、`--to` 不含，按 `--tz` 时区切日。**与 Azure 对账时保持 UTC**（Azure 全链路 UTC 日）；给运营看本地时区报表时用别的 `--tz` 重跑即可。
- 输出 `site_daily.csv`（canonical 格式，列见设计文档 §3）和 `site_daily.manifest.json`（参数、扫描行数、日志水位、口径注记）。同参数重跑结果逐字节一致。
- 建议在只读副本或低峰期执行；扫描按 id 分页，默认每批 5000 行（`--batch` 可调）。

`channel_map.yaml`（运营方维护，示例见 `examples/channel_map.yaml`）：

```yaml
channels:
  - channel_id: 7
    channel_name: azure-a
    account_label: account_a          # 不用真实姓名/邮箱
    azure_resource: rg-foundry/res-a
    deployment: gpt-5.6-dep           # Azure ModelDeploymentName
```

## 2. 离线对账

```bash
./usagetool reconcile \
  --site site_daily.csv \
  --azure azure_export.csv \
  --mapping azure_mapping.yaml \
  --threshold 0.03 \
  --out report/
```

输出：
- `report/reconcile_report.csv`：每行 `日期 × key × 指标`，站内值 / Azure 值 / 绝对差 / 差异率 / 原因标签；
- `report/reconcile_summary.md`：总量核对 + 超阈值计数 + 被跳过行清单。

`azure_mapping.yaml` 两种形状（示例见 `examples/`）：

**宽表**（Azure Monitor 指标导出整形后，推荐做 token 对账）：

```yaml
format: wide
date_column: Date
key_column: Deployment
site_key: deployment
columns:
  input_tokens: InputTokens
  output_tokens: OutputTokens
  cache_read_tokens: CachedTokens   # 可省略；省略即"未提供"
  requests: Requests
  cost: Cost
```

**长表**（Cost Management CSV，做金额+缓存 meter 对账）：

```yaml
format: meter_long
date_column: Date
key_column: ResourceId
site_key: azure_resource
unit_scale: 1000000        # meter 单位是 1M Tokens
columns:
  quantity: Quantity
  meter_name: MeterName
  cost: CostInBillingCurrency
  charge_type: ChargeType  # Refund/RoundingAdjustment 行自动单列，不计差异率
meter_rules:               # 顺序匹配，第一条命中生效
  - match: '(?i)\bcachd?\b|\bcd\b'
    direction: cache_read
  - match: '(?i)\bin(p|put)?\b'
    direction: input
  - match: '(?i)\bout(put)?\b'
    direction: output
```

## 3. 行为约定（与运营方核算规则对齐）

- 差异率 = `(站内 - Azure) / Azure`；分母为 0 → `N/A`；
- 一侧无数据 → `未提供`，不是 0；
- Azure 重复键行合并累加并打 `duplicate_rows_merged`；
- 未命中 meter 规则的行进「被跳过清单」，不静默丢弃；
- 最近 48h 的日期附 `timezone_or_late_arrival` 软标签（Cost 摄取延迟 1~2 天）；
- 站内侧标签由导出列自动触发：`local_estimate_used`、`upstream_usage_missing`、`client_disconnected`、`retried_on_another_channel`、`upstream_may_have_billed`、`cache_usage_estimated`、`mapping_missing`。

## 4. 需运营方在 Azure 侧执行的导出（对账数据来源）

> 全部在你们本地完成，工具只吃导出的脱敏文件。

**A. Azure Monitor token 指标（推荐日粒度、UTC）** — 对 token 量：

```bash
az monitor metrics list \
  --resource <认知服务账号资源ID> \
  --metrics ProcessedPromptTokens GeneratedTokens \
  --dimension ModelDeploymentName \
  --start-time 2026-08-01T00:00:00Z --end-time 2026-09-01T00:00:00Z \
  --interval P1D --aggregation Total --output json
```

注意：
- 用 CLI/REST 导出（诊断设置导出会丢维度）；指标保留 93 天，需按月及时导；
- `AzureOpenAIRequests` 可加导（带 StatusCode 维度，用于请求数分层比对）；
- **缓存 token 没有 Monitor 指标**，缓存对账只能靠 Cost CSV 的 cached meter；
- 新指标组（`InputTokens`/`OutputTokens`）如可用可一并导出，工具靠列映射兼容。

导出的 JSON 需整形成宽表 CSV（列：Date, Deployment, InputTokens, OutputTokens[, Requests]）——如不方便整形，把原始 JSON 给 Cloud，我们补一个 JSON 直读入口。

**B. Cost Management 日粒度导出** — 对金额与缓存：

门户 Cost Management → Exports（或 `az costmanagement export`），Actual cost、按天，确保包含 `Date / MeterName / Quantity / CostInBillingCurrency / ResourceId / ChargeType` 列。注意该导出是"月初至今整月覆盖重写"，取当月最终版即可。

**C. 同时提供**：`channel_map.yaml` 内容（渠道→账号标签→资源→deployment 映射）、生产 `FORCE_STREAM_OPTION` / `RetryTimes` / `ERROR_LOG_ENABLED` 实际值、期望对账时区确认（建议 UTC）。
